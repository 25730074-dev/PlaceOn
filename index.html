최종 사이트맵(2~3뎁스) 기준 화면 도면. 색상과 이미지를 배제하고 정보의 우선순위, 행동의 위치, 화면별 데이터 항목만 검증하기 위한 설계 도면임.

2. 화면을 늘리지 않은 판단

검토 항목판단
검색 조건(필터) 설정전용 페이지 대신 장소 검색 화면 상단의 조건 칩으로 처리
추천 결과별도 추천 페이지 없이 장소 검색 화면의 결과 목록으로 통합
랜딩 소개와 인증소개(로고·한 문장)와 로그인·회원가입을 두 화면으로 나눠 첫 인상과 입력 부담을 분리. 로그인 상태면 소개를 건너뜀
메인의 검색 진입메인 검색창은 두지 않고 하단 탭의 검색으로 일원화해 검색 진입 경로를 한 곳으로 유지
즐겨찾기와 기록 조회서로 다른 저장 목적이지만 마이 화면 하나에 탭으로 묶어 화면 수를 줄임
취향 설정가입 직후 입력과 이후 수정을 같은 화면으로 재사용
지도 화면별도 지도 페이지는 만들지 않고 메인(현재 위치)과 장소 검색(결과 장소 위치)의 지도 영역으로 처리

3. 이 도면에서 확인한 설계 판단

  • 화면 8개, 최대 3단계 — 랜딩 소개 · 로그인/회원가입 · 메인 · 장소 검색 · 상세 · 마이 · 취향 설정. 장소 검색의 결과 없음·오류는 같은 화면의 상태로 처리
  • 지도는 두 화면에서 역할이 다름 — 메인은 현재 위치 확인, 장소 검색은 결과 장소의 위치 확인. 번호 핀과 카드 번호를 맞춰 목록과 지도를 오가며 비교
  • 메인은 현재 위치 지도 + 주변 추천 — 검색창을 빼고 위치 확인과 추천에 집중. 검색은 하단 탭의 돋보기로 진입
  • 상단은 로고 헤더, 하단은 아이콘 탭 — 모든 화면에 같은 헤더를 두고 홈·검색·마이 이동은 하단 탭으로 일원화
  • 목록 카드 정보는 3개로 제한 — 모바일 세로 화면에서 한 번에 3건 이상 보이도록 배지를 카테고리·분위기·거리로 고정
  • 상세에서 목록 복귀 시 조건 유지 — 이 규칙이 지켜지지 않으면 목록과 상세를 반복 이동하는 문제가 그대로 남음
  • 취향 값과 장소 값을 같은 지정값으로 통일 — mood · priceRange · category가 일치해야 추천 점수 계산이 가능함
